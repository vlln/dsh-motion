# 三次冷启动：系统自己交了什么，别人怎么评的

2026-10-25。三个没参与制作的 agent，各自只拿到一句话题目和这个仓库的说明书，
从 `dsh-motion init` 开始做一条 8–12 秒的片子。**引擎没有给他们任何画法。**

| | 冷启动 1 | 冷启动 2 | 冷启动 3 |
|---|---|---|---|
| 题目 | 一杯茶凉掉的过程 | 地铁进站时的一阵风 | 一枚硬币在桌上转到停下 |
| 结果 | ✅ 11.4s · 4 镜 · 带音轨 | ✅ 11.0s · 3 镜 · 带音轨 | ✅ 10.8s · 3 镜 · 带音轨 |
| `check --deliver` | 六条全绿 | 六条全绿 | 六条全绿 |
| 画法来源 | 自己写的双版木口木刻 | 自己写的麻胶版三色套印 | 自己写的铜版画排线 |
| 用了 `kit/` 吗 | 没用 | 没用 | 没用 |
| 自评 | 82 | 77 | 75 |
| **独立盲评** | **51** | **55** | **37** |
| 一票否决 | 签名 21 < 25 | 签名 21 < 25 | 签名 10 < 25 |

## 三次都成立的三件事

1. **画法可以现写。** 三个 agent 各自发明了一种印刷媒介，没有一个人伸手要引擎给一个"版画函数"。
   这正是这套系统要证明的：风格是资产，不是 API。
2. **流程能被不认识的 agent 走完。** 三次都是从 `init` 走到 `check --deliver` 全绿，
   没有一次卡死，没有一次交不出音轨。
3. **自评会虚高 20–35 分。** 82→51、77→55、75→37。**每一次**都虚高，而且虚高的幅度随
   "作者投入的力气"增长。打分表里那句「自评不可信」现在有了三组数。

## 三个盲评人各自独立说出的同一句话

> 「矢量插画套了一层纹理。」

三种不同的版画、三个没通气的人、同一个诊断。所以它写进了 `protocol/打分表.md` 的
**媒介四道硬指标**：标记是刻掉的不是描上去的、版与版之间要错位、亮部是纸不是白颜料、
同一块颜色内部墨量不均。缺两条以上，媒介可信 ≤ 8，而且签名分也必然拿不到。

第三份评审还给出了一个关键算术：**即使把排线和纸色两项都判满分，缺毛口与版痕也把上限
压在 21 分，仍低于 25**。所以「像不像」不是尺度问题——是要件根本没做。

## 三次一起暴露的系统缺陷（已修）

| 缺陷 | 后果 | 修法 |
|---|---|---|
| `version -m "…"` 被吞 | 版本标题变成「版本 v1」，中文标题丢失 | `opt()` 同时认 `-m` 和 `--m` |
| `render --stills --out out/try` | ffmpeg 报错但帧已落盘、还打印成功 | 裸名自动补扩展名 |
| `check` 报 16.7ms | rAF 被 vsync 锁死，这个数只能证明"超了"，不能证明"多贵" | 直接计时 `setTime` 的绘制成本 |
| `audio.json` 的 `length`：手册说不写，校验说必填 | 两处打架 | 手册改成"可以不写，写了要一致" |
| `pad` 的 `root`/`chord` 没写类型 | 照字面写 `"root":"D2"` → NaN → 静音 | 写明 `root` 是 Hz、`chord` 是倍数数组 |
| `protocol/交付.md` 说音频落在 `out/bed.wav` | 实际是 `motion/assets/audio/bed.wav` | 改正 |
| `<skill>` 不是真路径 | 从片子根目录跑 `MODULE_NOT_FOUND` | 写成相对路径并说明 |
| 镜头表两份结构不同（SKILL 八节 / 模板三节） | 每个 agent 都要猜以哪个为准 | 八节改成"想清楚的清单"，不是文档小节 |
| "没有参考算不算新风格"没写 | 三个 agent 三种理解 | 写明：给题目不给参考 → 不走六步 |
| "空画面"没定义 | 只能猜 | 写明量法：96×54、亮度标准差 < 4、连续 0.3s |

## 诚实结论

**流程通了，画面没通。** 三个 agent 都能交出一部"能交"的片子，但没有一部是"能看"的片子——
盲评 37–55 分，全部触发签名否决。系统目前保证的是**下限**（不空、不静、有声音、能交付），
不保证**上限**（像不像那个媒介）。

下一步该动的不是流程，是 `protocol/打分表.md` 里那四条硬指标**怎么在画的阶段就落进代码**——
比如版画的刻线，不应该等到审片才被发现是描边。
