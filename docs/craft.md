# 让 agent 做出「画出来的动画」

> 这份文档不是制作方法，是**系统的设计约束**。它回答一个问题：为什么同一套渲染器，别人能做出像画一样的片子，我们的 agent 做出来是色块加缓动；系统要补到什么程度，agent 自己才能做到。

## 一句话

**系统的产出，等于它让什么变便宜、让它照着什么读、让它被什么卡住。** 三样都指向「搭」，出来的就是色块；三样都指向「画」，出来的才像画。

## 三条腿

缺一条都不成立，顺序是「先有能力，再有标杆，最后靠判据收敛」。

### 一 · 能力：让「画得像」成为阻力最小的路

Agent 不会因为手册说「要画得像」就去画。它只会用环境里最便宜的东西。现在最便宜的是「矩形 + 渐变 + 缓动」，于是出来的是色块。

能力这一条的要求不是「提供更多工具」，而是：**提供之后，画得像比画得平更省事。** 具体是两样：

| 能力 | 它让什么变便宜 | 没有它会怎样 |
|---|---|---|
| **材料通道**：把已经画好的形整体重画成材料（笔触／炭／绢／网点／玻璃） | 「画得像」从几千笔的工程变成一次调用 | 每个 agent 各自手写几百行笔刷，最后一个都没写完 |
| **拿来通道**：公版画／摄影可以直接当世界用，不只是当贴图 | 「拿一张真的」比「画一张假的」更省事 | agent 只能造，造出的永远比真品薄 |

判断标准：**能力上线之后，平庸的做法必须变贵。** 如果一个新功能让「继续画色块」和「开始画材料」一样便宜，它就没有意义。

### 二 · 标杆：让它有可读的参照

Agent 的水平上限是它读过的东西。库里全是单镜头的循环样板时，它只能模仿单镜循环。

所以系统要有**几条完整的、源码可读的、够好的片子**，覆盖不同材料。不是文字描述「应该怎样」，而是它可以打开、抄结构、换内容、改尺寸的活样本。**样板即规格。**

要求：
- 源码可读（不是打包产物，不是只有成片）；
- 一条片子一个媒介，不要「八个格子展示八种风格」——那是画廊，不是可抄的样本；
- 每条带一段**拆解**：这一条靠什么成立（哪一道工序、哪一处决定性细节）。

### 三 · 判据：让它自己知道偏了

人看一眼就知道「太扁了」。agent 不知道自己偏在哪，于是只能交第一版能跑的。这一条现在几乎为零，也最致命。

系统要把「像不像」变成 agent **自己能算、能看**的东西：

- **并排图**：原作 vs 自己，一键出，它自己能看出差在哪；
- **可计算的指标**：平涂占比、纹理密度、与参考图的色板距离——把「扁平」变成数字；
- **可比较的报告**：每次 `check` 都给一份，改一次收到一次反馈。

没有这一条，前两条都会被浪费：有能力也不会用对，有标杆也不会对照。

## 原则：系统规定「什么算合格」，不规定「怎么做」

我们写的是**环境**，不是**剧本**。不规定先做静帧还是先铺六镜、不规定先画哪一层、不规定用哪种笔触。我们只负责让「做透一镜」比「铺满六镜」更省事，让「像」有数字、让「不像」有报警。

区别在于：剧本换个题材就作废，环境换个题材还在。

## 怎么算验收

**给它一条没见过的 brief，看它能不能自己出并排图、自己发现「太扁」、自己回去改。** 做不到，说明缺的是判据或标杆，不是提示词。

这条验收必须能重复：换 brief、换 agent、冷启动（不读我们这次对话），结论应该一样。

## 不做什么

- **不做通用笔触库**：无底洞，而且「拿一张真画」绕开了它。笔触通道只需要覆盖「代码必须自己画」的那部分。
- **不加更多画法动词**：动词解决「能不能」，不解决「像不像」。
- **不把做法写进技能**：做法会过期，判据不会。
- **不用人工打分当门禁**：会腐化。要么能算，要么做成必交产物（并排图）。

## 现在的状态（2026-10-24）

三条腿各落到什么程度，以及**还没落地的部分**：

| 腿 | 已经有的 | 还缺的 |
|---|---|---|
| 能力 | `ctx.paint.space`（透视）、`ctx.paint.sprite`（像素角色）、`ctx.medium`（四个重画通道 + 胶片）、`ctx.still`（画一次）、`init` 默认从 `plate` 起手 | 四个重画通道**全是硬边不透明**：雾、水汽、烟这类软材质做不出来（冷启动第三次就卡在这） |
| 标杆 | `plate`（拿来的画 + 演员）、`guide`（纸上印刷）、`tree`（绢本水墨）、`street`（代码画 + 画一次上材料），各带拆解 | 没有一条**多镜头**的样板；四条都是单镜 |
| 判据 | `check` 末尾的 look 行（solid / texture / contrast）、`out/look/vs-ref.jpg`、`--strict` 只拦空画面 | 一个标量判不了"像不像画"：实测里一条画出来的夜街（7.5）和一张扁平的日景（7.7）撞在一起。判据只在"和参考比"时可靠 |

### 改造前的基线（用新的判据量旧作品）

| 帧 | 大块同色 | 局部细节 |
|---|---|---|
| 参考片（梵高段） | **1%** | **39.1** |
| 我们的五条 · 最好的那条（梵高版） | 36% | 19.9 |
| 我们的五条 · 原版（四帧取样） | 58–82% | 5.0–7.7 |

原版在接触表上"看着还行"，量出来是一帧 **82% 是一块颜色、局部细节只有参考片的 1/7**。
这就是"为什么它看着不像画"的数字版答案，也是判据这条腿存在的理由。

**验收标准没有变**：给它一条没见过的 brief、一个冷启动的 agent，它能不能自己出并排图、
自己发现太扁、自己回去改。这条记录写在下一节。

## 验收记录 · 冷启动（2026-10-24）

同一句 brief（雨后停车场、无人、结尾停在具体的东西上），两次独立的冷启动 agent，只给手册和 CLI。

| | 第一次 | 第二次（加时间预算） | 第三次（加默认架构） |
|---|---|---|---|
| 交付 | ❌ 15 分钟没出场景 | ✅ 20 分钟交片：12s 3 镜、check 绿、v1 | ✅ 成片 mp4 + 接触表 + PLAN/CREDITS + v2 |
| 路线 | 拿（默认 plate） | 搭（`init --blank` + `space`） | **混合**（照片当世界 + 代码画玻璃水汽） |
| 素材 | 找了 7 张、全记许可 | 0 张，判断"贴图会毁掉机位与光位一致性" | 1 张 CC0 照片（SuperSpin），两轮内选完 |
| 判据 | 没走到 | ✅ 看了 look，**改了三次** | ✅ 抓到一次假数字（16.3 是水汽被裁光的假象，真值 8.2），补回 10.9 |
| 材料 | — | ❌ 一次没碰 `ctx.medium` | ✅ 照片给材料、代码补照片做不到的那层 |
| texture | — | 2.7 | 10.9（参考 39） |
| 声音 | — | ❌ 放弃 | ✅ 合成了一条 |

**三个结论：**

1. **判据这条腿成立了。** 陌生 agent 看到数字会改东西，而且能自己诊断到"水面缺天空反射"这一层。
2. **光有数字不够，还要有标尺。** 2.7 是个孤立数字，它不知道算好算差；给了标尺之后，
   "该不该回去改"才变成可回答的问题。
3. **默认起点决定路线。** 第一次默认就选了"拿"；第三次从 `street` 起手，做成了**混合**——
   照片给脏和旧，代码补照片做不到的那一层。**正确的分工是起点带出来的，不是提示词说服出来的。**
4. **判据能抓到自己看不见的回归。** 第三次的 `destination-in` 把水汽整层裁掉，画面"看着还行"，
   是数字先露馅（16.3 假高 → 实际 8.2），它才去查合成方式。这一条比"数字能打分"更值钱。

**当时还没成立的：** 材料通道在真实使用里不会被主动想起（第二个 agent 怕它慢）。这说明缺的不是
文档，是一个**默认架构**。

**已补（同日）**：`ctx.still(draw)` 把"画一次"变成一个动词，`templates/street` 把
"画一次 → 过材料 → 细线画在上面"做成一整条可抄的片子，拆解写在 `docs/exemplars/street.md`。
另外修正了材料通道在暗部的问题：暗笔画不描厚涂边（否则夜戏糊成毛皮），笔触尺寸按画幅给（`size`）。
