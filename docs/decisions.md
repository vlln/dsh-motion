## D001 · 渲染栈固定为 canvas 2D + WebGL

- **日期**：2026-10-22
- **状态**：生效

### 背景

参考产品（Claude Motion）允许 agent 按任务自行选择渲染面（DOM / canvas / WebGL / 混合），
因为它不拥有渲染器，只拥有"预览 + 导出 + 批注"的宿主壳。我们要决定是否照做。

### 决定

内核只提供一种渲染面：**每个场景拥有自己的 canvas（2D 或 WebGL），内核合成到显示画布**。
场景模块的契约是 `render(t)`，不含 DOM。

### 备选

| 方案 | 优点 | 为什么不选 |
|---|---|---|
| 自由栈（agent 每项目选） | 风格上限最高，文字排版免费 | 契约碎成 N 份：命中、审计、确定性、可编辑、导出验证都要按表面各实现一遍；门禁只能退化成"像素变了没有" |
| 混合（场景可选 DOM / canvas） | 兼顾文字与图形 | 需要两套契约 + 两套坐标系；跨场景转场要同时合成两种表面；门禁分叉 |
| DOM 单栈 | 排版最省 | 丢掉真 3D（CSS 3D 是仿射变换）和逐像素能力；60fps 下元素多时重绘成本高 |

### 依据

1. **我们卖的是"每一帧都可验证"**，不是"什么都能画"。栈固定是这条承诺的前提。
2. **参考产品的自由是用窄编辑面换的**：它的 Tweaks 只有文本 / 数字 / 段长 / 速度四类，
   因为只有这些能被通用地发现；我们要任意参数、调色板、覆盖、快照回退，就必须有统一契约。
3. **文字短板不是栈造成的**：canvas 的 `fillText` 与 DOM 使用同一套字体整形引擎
   （Chromium 里是 Skia + HarfBuzz），差的只是断行与测量——那是一个布局层，不是另一种渲染器。
4. **捕获方式不受栈限制**：导出走 `page.screenshot()`（整页截图），不是 `canvas.toDataURL()`，
   所以页面上多一层什么都能拍到。真正的约束是"同一时刻必须能重放出同一帧"。

### 代价

- 文字排版要自己写（断行、禁则、测量缓存、省略号）；
- CSS 独有的声明式布局（flex/grid、`shape-outside`）无法直接复用；
- 高级排版（竖排、注音、两端对齐 + 连字符）短期做不到；
- 生态里的 Web 排版组件无法直接使用。

### 什么会让我们改主意

- 中文讲解片成为主产出，且**布局层做完后**仍有肉眼可见的排版差距（不是"差一点"，是"不能用"）；
- 需要竖排、注音或两端对齐这类 CSS 布局引擎才能做对的排版；
- 出现"必须复用某个 DOM 组件（如图表库的 DOM 渲染器）"的硬需求。

改法不是"整体换 DOM"，而是给内核加**一个受控的文字表面**（内核拥有、契约不变），
见 `docs/primitives.md` 的"文字"一节。

## D002 · 文字排版由内核自持，不引入 DOM 文字层

- **日期**：2026-10-22
- **状态**：生效（P1 实现）

### 背景

文字目前由每个场景自己调 `ctx.text(slot)` + `fillText`，换行逻辑是
`String(text).split(' ')`——中文没有空格，永远不会换行。同时命中测试拿不到"这个文本框属于哪个槽"，
所以面板无法"点文字 → 改文字"。

### 决定

新增内核原语 `ctx.drawText(slot, opts)`：**排版、绘制、登记元素、暴露槽身份**在同一个函数里完成。
场景不再自己换行、不再自己算行高。

### 备选

- **每场景自己排版**：现状。每个场景重复实现，且必然出现"这个场景换了那个场景没换"。
- **引入 DOM 文字层**：质量最好，但违反 D001 的契约一致性。
- **引入 Satori/Resvg 做 HTML 子集排版**：能力强，但引入第二套坐标系与一套 wasm 依赖，
  且它输出的是位图块，命中与槽身份仍需另做。

### 依据

- 断行是纯函数问题：UAX #14 有现成实现（`css-line-break`），加上 `Intl.Segmenter` 取词边界；
- 字距/字重/连字由浏览器整形引擎负责，canvas 已经支持 `letterSpacing` / `fontKerning` / `fontVariantCaps`；
- 把"槽身份"放进绘制调用，是让命中测试、审计几何、面板编辑三件事共用一份数据的最小方式。

### 代价

- 排版质量上限低于浏览器布局引擎（无自动连字符、无两端对齐、无竖排）；
- 需要自己维护测量缓存，否则每帧 `measureText` 会成为热点。

### 什么会让我们改主意

- 出现竖排/注音/两端对齐的真实需求；
- 断行实现被证明在某些语言（泰文、阿拉伯文）上不可靠。

## D003 · 导出 = 整页截图 + 逐帧重渲，不做视频转码

- **日期**：2026-10-22
- **状态**：生效

### 背景

导出可以走两条路：录屏/转码（快，但帧率与分辨率被锁死），或按目标帧率逐帧重渲（慢，但任意参数）。

### 决定

`capture.mjs` 逐帧 `renderAt(t)` → `page.screenshot(jpeg)` → `image2pipe` → `libx264`。
帧率、时长、分辨率都由这次运行决定，不缓存中间视频。

默认 60fps（两个参考产品都锁 60：动效片的观感差异明显），并支持 `--supersample 2`：
页面按 2× 设备比例渲染再降采样，因为文字是在捕获分辨率上光栅化的。

### 依据

- 参考产品同时提供 15/30/60fps：视频只能向下转码，不能向上，说明它也是重渲；
- 逐帧重渲让"预览与导出同源"成立（同一个 `render(t)`），这是"改一处其余不变"的基础；
- 我们实测 570 帧约 11 秒（≈19ms/帧），重渲成本可接受。

### 代价

- 每次导出都是全量计算，没有增量导出；
- 2× 超采样会让耗时接近 4 倍。

### 什么会让我们改主意

- 出现"半小时长片"的需求（那时需要分段导出 + 拼接）。

## D004 · 批注是人说的一句话，不是一个并行通道

- **日期**：2026-10-23
- **状态**：生效

### 背景

面板曾经自己收批注、自己存、自己回。人按了 "Send to Claude"，界面关掉，什么都没发生；
agent 只有在主动来拉的时候才看得见。宿主的会话模型其实给了三种投递：**跟进**（开一个新回合，
叫醒 agent）、**插入**（下一步吃掉，叫醒）、**注入**（放进下一步的上下文，**不叫醒**）。
选错了动词，就等于把"等 agent 来拉"换了个名字。

### 决定

- 批注由人写，就走**人的那条路**：作为一条人说出的消息进对话（跟进/排队）。
- 面板只保留**钉子**：时刻、区域、元素、处理状态。没有第二套聊天，没有回复气泡，
  没有"发送给 Claude"的开关。
- agent 的话说在对话里；改完之后用 `motion_comments resolve` 把钉子标成已处理。
- 独立打开预览（没有会话）时，批注如实显示"未发送"，不假装发出。

### 备选

| 方案 | 优点 | 为什么不选 |
|---|---|---|
| 用**注入**送批注 | 不打断，可批量 | 注入**不叫醒**：agent 闲着就永远看不到；而且作者身份从"人"变成"系统" |
| 保留面板内的 `reply` 线程 | 面板自洽，不依赖对话 | 第二套聊天，两套真相；面板的回复从不出现在人读的地方 |
| 每条批注自动开一个回合 | 即时 | 打断 + 每次框选一次模型调用，人会开始不敢用 |

### 依据

- 宿主的投递模型（跟着/插入/注入 的语义与唤醒行为）。
- `gate:card` 的端到端证据：面板发一条批注 → 对话里出现 `[批注] 0:03.20 · title` 消息 →
  钉子的 `sentAt` 被写上；`gate:comments` 的负控证明 `reply` 通道已经不存在。

### 代价

- **一条批注 = 一个回合**（跟进是"一条消息一个回合"）。五条就是五个回合。这是**要的**：
  一条批注对一个回合，哪条被处理、哪条被漏，一眼能看出来；合并成一条反而对不上钉子。
  唯一真实的成本是上下文变长，那是干活本来就要花的。
- **没有会话就没有批注入口**。独立打开预览时不显示批注区、不能拖框；要看批注用命令行。
  这样系统里只有一种批注：写下来就是为了发出去。
- 人在画面上框选时，消息里只有时刻和元素名；精确矩形仍在钉子里，agent 要看得自己去看。

### 什么会让我们改主意

- 宿主提供"多条合成一条消息"的批量投递；
- 或批注需要在 agent 忙碌时**静默**送达（那就该用插入，而不是跟进）；
- 或面板被证明能在没有会话的场景里独立使用（例如离线剪辑）。

## D005 · 一部片子属于会话的工作区，不属于插件的安装目录

- **日期**：2026-10-23
- **状态**：生效

### 背景

插件把自己的安装目录当成"项目"：面板读包里的 `timeline.json`，九个工具读写同一个文件，
场景代码编译进面板包。于是任何会话一打开看到的都是同一部示例片；agent 想改画面只能去改
插件包里的场景代码——**在会话工作区之外**。用户的原话是"完全不符合逻辑"。

### 决定

- 片子住在 `<会话工作区>/motion/`：`timeline.json`、`scenes/*.mjs`、`assets/`、`out/`、`.snapshots/`。
- 没有片子的工作区显示空状态，不借示例片。
- `motion_project` 建片：写时间轴 + 复制一份起始场景到 `motion/scenes/blank.mjs`。
- 场景在运行时加载：内置 id 用包里的，其余从片子的 `scenes/` 动态 import。
- 面板挂在 `/plugins/dsh-motion/p/<会话>/`，所有相对地址（时间轴、场景、素材、接口、导出）
  自动落到同一个目录。
- 包里的 `timeline.json` 降级为开发和门禁的示例，任何会话都不读它。

### 备选

| 方案 | 优点 | 为什么不选 |
|---|---|---|
| 继续用安装目录当项目 | 零改动 | agent 必须在工作区外写代码；所有会话共享一部片子 |
| 会话目录下用隐藏的 `.motion/` | 不污染文件树 | 片子是内容不是状态，用户要能看见、能提交、能改 |
| 场景仍编译进包 | 简单、启动快 | agent 写的场景永远加载不了，"做一个新片子"等于改插件源码 |

### 依据

- `gate:client`：在隔离工作区里预置一部片子，断言面板挂到 `/p/<会话>/`、时间轴与场景来自
  工作区、一次面板写入落在工作区、越界路径被拒。
- `gate:card`：真实会话里让 agent 调 `motion_project` 建片 → 渲染 → 发批注，最后断言
  `motion/timeline.json` 和 `motion/scenes/blank.mjs` 出现在**工作区**里。
- 空状态：同一套界面对没有片子的工作区显示"还没有片子"，不显示示例。

### 代价

- 片子多了一个目录，用户要决定是否提交（建片时写了 `.gitignore`：`out/`、`.snapshots/`）。
- 场景从工作区动态加载，意味着场景代码在宿主进程里被 import（node 侧）和浏览器里被 import
  （面板侧）：信任边界从"包内代码"扩大到"工作区代码"，和工作区里的脚本同级。
- 没有片子的工作区里，面板除了空状态什么也做不了——这是有意的。

### 什么会让我们改主意

- 用户希望一个工作区里放多部片子（那就需要项目清单，而不是固定 `motion/`）；
- 或者希望片子跟随会话而不是工作区（同一目录多个会话各有一部）。

## D006 · 不给 agent 工具面，给 skill 和命令

- **日期**：2026-10-23
- **状态**：生效

### 背景

插件先后长出了十一个工具（建片、写场景、改字、调参、渲染、导出、批注……）。每个工具都是
一个窄接口，而且每一个都在替 agent 做决定：片子放哪、场景怎么落盘、渲染器由谁启动。
为了让这些决定不泄漏，又加了路径隐藏、系统提示和"不要做某事"的指令——补丁摞补丁。

用户指出：agent 做动画不需要任何工具，它需要的是**知道这个库怎么用**，然后自己写、自己跑。

### 决定

- 插件**不再注册任何工具**。
- `skills/dsh-motion/SKILL.md` 是唯一的手册：布局、时间轴、场景契约、`ctx` 原语、命令。
- `dsh-motion` 命令（init / validate / render / export）是唯一的执行入口；插件把自带的
  `bin/` 挂到宿主 PATH 上，agent 不需要知道包在哪。
- 插件保留：内核与脚本、skill 注册、按会话挂载的预览路由。
- 面板的数据接口（改字、调参、导出、批注）只服务人，不再是 agent 的 API。

### 备选

| 方案 | 优点 | 为什么不选 |
|---|---|---|
| 继续用工具面 | 每个动作都可校验、可发现 | 接口永远缺一块；知识得靠提示补；把编程 agent 当表单填 |
| 给 skill 但保留几个"重要"工具 | 折中 | 两套入口，模型会挑省事的那套，等于没删 |

### 依据

- `gate:surface`（17/17）：真实 Cordis 入口下**零工具注册**，skill 与命令齐备。
- `gate:card` 待按新形态重写（当前不在 `check` 里）：目标是真实会话读 skill、写文件、
  跑命令，末尾断言片子与静帧落在工作区。
- 全量：22 组通过。

### 代价

- 校验从"工具参数校验"变成"命令失败"：`dsh-motion validate` 要真的跑一次。
- agent 必须能执行命令；shell 不可用的环境里这套形态跑不动。
- 面板的"自动弹出"原本绑在渲染工具的 toolview 上，现在需要另找触发点。

### 什么会让我们改主意

- 出现必须由工具保证的副作用（例如原子写入、并发写保护）；
- 或者 agent 反复在同一类错误上卡住，说明手册不够，而不是接口不够。

## D007 · 没有片子时，面板给的是会动的方向，不是文字样板（已被 D008 取代）

### 背景

空工作区最早是一页"风格样张"：四张卡片，用配色和字体排一个静态小画面，下面跟一段提示词。
用户看了一眼就说"太丑了，全是文字"。第一次改成了四段真动画（深空 / 纸感 / 冷光 / 黑白），
仍然被打回："还是太粗丑"。两次都不是排版问题，是**参考系**问题：我们按自己的想象编了四种风格，
而真正好看的动效版面长什么样，行业里已有现成答案。

用户指的参考是 [WebMotion](https://webmotion.superhq.ai/)（superhq 的浏览器端确定性合成器）：
它的首页 hero 是一段真实合成的片子，语言极克制——近黑底、等宽大写微标签、宽字距、
一条 1px 分隔线、一个蓝色强调、墙签式排版，运动的只有柱列与数字。

### 决定

空工作区是**一套**东西，不是四套风格：同一套版式语言，四个不同的动作习作。

- **语言**（取自 WebMotion hero，不搬它的内容）：近黑底 `#0b0b0c`、微标签 `#8a8a88` 等宽大写
  `0.26em` 字距、大标题 `-0.015em`、唯一强调 `#5b83ff`、一条 hairline、大量留白。
- **四张卡**：`基线`（柱列按顺序从基线长出来，带 FRAME 268 计数）、`展签`（墙签排版 + 幽灵编号）、
  `网版`（点阵从中心向外衰减显影）、`计时`（数字 000→268 滚动 + 一条带蓝色针脚的进度线）。
- 每张仍是**真动画**：canvas 2D、纯时间函数、6 秒循环、同一只时钟、离屏暂停、
  `prefers-reduced-motion` 停在稳定帧；淡入淡出用底色遮罩，不调整张画布 alpha。
- 选中才出现提示词（渐进披露），并且自动滚到提示词；发送走批注同一条通道。
- 卡片改为**单列 16:9**：2 列时每张只有 200px 宽，墙签排版在这个尺寸下必然糊成一团。

### 备选

| 方案 | 优点 | 为什么不选 |
|---|---|---|
| 四种互相独立的风格 | 覆盖广 | 摆在同一个面板里像杂货铺，不像一套作品；用户两次都嫌丑 |
| 每张卡渲一段 MP4 当缩略图 | 最"真" | 空状态要下载几 MB 视频才显示，离线/首屏都吃亏 |
| 继续用图片当缩略图 | 可控 | 图不是这个引擎画的，点进去会得到另一种片子 |
| 保持 2 列网格 | 一屏看到更多 | 200px 宽放不下微标签 + 大标题，字号一缩就脏 |

### 依据

- `out/ui-empty-bundle-panel.png`、`out/ui-empty-bundle-picked.png`：真实构建产物（`lib/app.js`）
  在 460px 面板宽度下的空状态与选中态；四张 canvas 都有非零像素。
- 参考实拍：`out/webmotion-hero.png`、`out/webmotion-full.png`；场景源码
  `site/src/scenes/hero.js`（字号、字距、颜色、缓动都写在那里）。
- 全量门禁 22 组通过（exit 0）。

### 代价

- 只有一种语言。用户如果想看"完全不同的另一种风格"，得再加一套，而不是换一张卡。
- 四张深色版式叠在浅色面板里占视觉重量；页面滚动长度也从一屏变成三屏。
- 仍是**示意**：选中后由 agent 从零写场景，不保证一比一复现那 6 秒。

### 什么会让我们改主意

- 用户要的风格明显不止一种（例如同时要"深色编辑部"和"明亮品牌片"），就把画廊改成
  语言分组，每组四张。
- 如果多数人选完只会说"就按刚才那张做"，说明该把习作升级成可实例化的模板
  （`timeline.json` + 场景模块 + 调色板），而不是继续画示意。

## D008 · 空工作区是一片动效广场：瀑布流、能播放、提示词可复制

> 取代 D007。D007 的"四个习作"被用户判为"还是太粗丑"，并给了真正的参考。

### 背景

用户给的参考是 [motionface.cc](https://motionface.cc/)（vibe-motion 的"探索动效广场"）：
瀑布流的视频缩略图，每条带时长、标题、分类、作者；点开是详情弹窗（播放器 + 元信息 + "复刻"），
复制"复刻"提示词后，agent 会下载参考视频、还原动画、建仓库并回填绑定。

这解释了两轮返工：我们一直在改*单张卡*的好坏，而用户要的是*一片可逛的墙*。
单张卡再精致，也不构成"探索"。

### 决定

空工作区 = 动效广场。10 条动效，共享一套版式语言，按分类可筛，点开可看可复制。

- **瀑布流**：CSS `columns`，每张卡按自己的比例（16:9 / 4:5 / 4:3 / 3:4）排；
  面板窄时 2 列，<380px 时 1 列。
- **卡面**：真实动画（canvas 2D、纯时间函数、6 秒循环）+ 时长角标 + 标题 + 分类小标；
  同一只时钟驱动全部，离屏暂停、隐藏标签页暂停、`prefers-reduced-motion` 停在稳定帧。
- **分类**：全部 / 文字排版 / 信息图解 / 界面演示 / 场景叙事 / 背景特效 —— 是筛选，不是新页面。
- **详情**：弹窗里把那条放大重播（舞台高度封顶 52vh），下面是标题、分类、时长、提示词，
  两个动作：`复制提示词`、`让 Agent 复刻`（发到对话，和批注同一条通道）。
- **提示词是我们的**：不下载视频、不要求 Remotion、不建仓库。它描述画面与动效，
  要求写进 `motion/`（timeline.json + scenes），跑 `dsh-motion validate`，再交关键帧。

### 备选

| 方案 | 优点 | 为什么不选 |
|---|---|---|
| 继续优化单张卡 | 成本低 | 用户要的是"逛"，不是"看一张" |
| 每格塞一段真实 MP4 | 最接近参考 | 空状态要下载几十 MB；我们的引擎本来就能实时画 |
| 照抄 motionface 的互动 | 形态一致 | 它的复刻链条是"下载 → Remotion → GitHub 绑定"，我们没有这套基础设施，也没必要有 |
| 一条大卡 + 缩略图条 | 聚焦 | 面板太窄，详情弹窗已经承担了"放大看" |

### 依据

- `out/ui-explore-bundle-top.png`（瀑布流）、`out/ui-explore-bundle-mid.png`（中段）、
  `out/ui-explore-bundle-sheet.png`（详情弹窗）——全部来自构建产物 `lib/app.js`，460px 面板宽。
- 筛选实测：点「场景叙事」后只剩 `tree`、`orbit` 两张卡。
- 全量门禁 22 组通过（exit 0）。

### 代价

- 10 段动画就是 10 份要维护的绘制代码；改版式语言要动十处。
- 首屏 10 张 canvas 同时在跑（已限到 30fps、离屏暂停），仍比空白页贵。
- 仍是**示意**：选中后由 agent 从零写场景，不保证一比一复现那 6 秒；"复刻"给的是文字处方，
  不是可执行的模板。
- 与参考相比缺两样：作者/点赞这类社区信息，以及"复刻后回填绑定"的闭环。

### 什么会让我们改主意

- 若 "复刻" 被频繁使用，说明这些卡应该升级成**真模板**（timeline + 场景 + 调色板），
  选中即生成，而不是每次让 agent 重新写。
- 若用户需要自己上传参考视频（像 motionface 那样从视频复刻），那是另一条入口，
  得先有素材通道，不能靠现在的暗示意硬撑。

## D009 · 广场要有"片感"：一块大图领衔，八套色，文字退到二线

> 取代 D008 的排布与视觉。D008 的瀑布流被用户判为"风格完全相同、UI 粗糙、全是文字"。

### 背景

D008 的十张卡共用一套深色编辑部语言：同样的黑底、同样的等宽小字、同样的细线。
单看一张成立，摆成一片就是"同一张图重复十次"；再叠上标题、分类小胶囊、说明段、六个筛选项，
屏幕上全是字，没有一张图在争眼睛。

### 决定

1. **每张卡有自己的颜色和字体**：亮黄绿（黑字）、米纸（衬线 + 铁锈红）、深紫（洋红光晕）、

   十张卡，八套底色，四种字体角色（无衬线大字 / 衬线 / 等宽 / 界面）。
2. **一块主图领衔**：第一张 16:9 满宽，其余进两列瀑布流；层级靠尺寸，不靠标签。
3. **文字退到二线**：删掉每张卡下的分类胶囊；筛选从六个胶囊改成一行带下划线的文字标签；
   头部只留「探索动效 + 10 段」，不再写说明段。
4. 点开的详情保持不变：放大重播 + 提示词 + 复制 / 让 Agent 复刻。

### 备选

| 方案 | 优点 | 为什么不选 |
|---|---|---|
| 只换配色 | 便宜 | 版式和字体仍是同一套，"重复十次"的感觉还在 |
| 更多卡（20+） | 显得丰富 | 绘制量翻倍，用户要的是"好看"，不是"多" |
| 保留分类胶囊 | 信息完整 | 12 个胶囊本身就是噪音，筛选用文字标签足够 |

- 十段动画十套配色，后续调统一（比如换品牌色）要逐张改，不能改一个变量。
- 主图只有一张；若以后内容变多，需要"轮换主图"或按分类各给一张。
- 仍是示意：提示词给的是处方，不是模板。

### 什么会让我们改主意

- 若用户觉得"颜色太杂、不像一个产品"，就回到一套品牌色 + 靠内容差异取胜；
- 若主图被频繁点开而其余卡很少被点，说明该改成"主图 + 横向三条"而不是瀑布流。

## D010 · 样板是三个"世界"，不是七套配色

> 取代 D009 的"八套色"。用户给的三个参考帧说明了差别：那是三种**整体美术方向**，不是同一张卡换色。

### 背景

D009 让每张卡有自己的颜色和字体，但版式仍是同一套"深色底 + 小标签 + 细线"；
用户看了三个参考（产品片：笔记本 + 悬浮步骤卡；图鉴：手绘对页；榜屏：透视倾斜的排行榜），
指出"应该以整体的大风格作为不同的样板"。

### 决定

样板按**世界**划分，一个世界一套完整的美术方向，画面里所有元素都可以动：

1. **产品片**（16:9，主图）：暖色房间 + 景深虚化、一台笔记本（屏幕里是浏览器界面）、
   键盘透视格、四张半透明步骤卡依次浮入、顶部胶囊写"Planning with MCP 0/4"。镜头缓慢呼吸。
2. **图鉴**（4:3）：米色纸对页、青色标题条、等宽小标签 + 衬线数值、虚线引线、蓝灰手绘猫、
   青色扫描器扫过、绿色芯片编号数字滚动、右下角画出芯片与标注。
3. **榜屏**（16:9）：深色空间里一块透视倾斜的排行榜屏幕，表头 + LIVE 点、六行名次/名字/分数、

4. 保留两个抽象世界：**动起来**（亮黄绿凯旋字）与**树**（黑金）；再加**轨道**（深蓝星场）

### 备选

| 方案 | 优点 | 为什么不选 |
|---|---|---|
| 继续加配色 | 便宜 | 换色不产生"世界"，用户已经否过一次 |
| 只做三个参考世界 | 聚焦 | 三个覆盖不了"文字排版/背景特效"，画廊会缺类 |
| 用生图做缩略图 | 最像 | 这台机器没有配置图像生成；而且图不是这个引擎画的 |

- `out/ui-explore-bundle-top.png`、`out/ui-explore-bundle-mid.png`、`out/ui-explore-bundle-sheet.png`：
  构建产物 `lib/app.js` 在 460px 面板宽度下的首页、后半段与详情。

### 代价

- 每个世界都是一段独立插画代码（产品片 ~120 行、图鉴 ~180 行），改一处要整段理解。

  "参考帧 + 提示词"的组合，而不是继续用代码画。

## D011 · 样板按"运动语法"分，而且 3D 走真 WebGL

> 用户问的是能力：这些参考能不能做？做完之后，样板该按"大方向"分，而不是换字换色。

### 结论（能力）

| 参考里的动作 | 我们的做法 | 结论 |
|---|---|---|
| 面板围成一圈旋转（真 3D、带透视） | WebGL 场景 + three（引擎已有 `kind: 'webgl'`，`src/scenes/orbit.mjs` 是现成例子）；画廊里新增 `carousel` 用同一个 three 懒加载块 | **能** |
| 镜头持续运动 + 前面卡片进入/退出 | 2D：整体 `scale/translate` 做推近，卡片 `outCubic` 依次入场、结尾退场；3D：直接动相机 | **能**（已实现） |
| 手绘页 + 打字机 + 扫描枪从屏外进来 | 文字按进度截断绘制（光标闪烁），物体位移从画布外进入 | **能**（已实现） |
| 排行榜镜头自下而上 + 名次上升 | 整块 `translate` 做镜头爬升，行 y 坐标随 `swap` 插值，名次标签跟着位置走 | **能**（已实现） |
| 参考里的实拍/三维渲染材质 | 我们是代码绘制；要照片级，需要素材通道（上传图/视频或 3D 模型） | **不能凭空** |

### 决定

1. **3D 用真 WebGL**，不用 2D 假透视：`carousel` 是八张海报围成一圈、绕 Y 轴自转，
   纹理由 canvas 画好后做 `CanvasTexture`，相机 `PerspectiveCamera`。three 只在
   这张卡进入视口时才加载（懒加载），1.6 MB 的块不进首屏。
2. 三个 2D 世界补齐"运动语法"：产品片的推近与卡片进出、图鉴的打字机与扫描枪入场、
   榜屏的镜头爬升与名次交换。
3. 样板按世界分：产品片 / 图鉴 / 榜屏 / 旋转海报 / 动起来 / 树 / 轨道 / 光晕。

### 依据

- `out/ui-explore-bundle-top.png`、`out/ui-explore-bundle-mid.png`：构建产物 `lib/app.js` 在 460px 面板下；
  旋转海报、榜屏换位、图鉴打字机都在画面里。
- `npm run check`：22 组通过（exit 0），其中 `gate:split` 仍保证 2D 片子不加载 3D 块。

### 代价

- 画廊首次滚到 3D 卡时会拉 1.6 MB（three），比纯 2D 版本重；已按视口懒加载。
- 3D 卡的纹理是 256×320 的 canvas，放大到全屏会软。
- 素材边界没变：没有照片/实拍/模型导入，就没有参考里那种材质。

### 什么会让我们改主意

- 若 3D 卡被证明没人点，就退回 2D，省掉 three 的体积；
- 若要真正对齐参考的材质，先补素材通道，再谈模板。
