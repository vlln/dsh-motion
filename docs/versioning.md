# 版本（讨论稿）

目标：每次 agent 完成一次修改或新做一段动画，都成为一个**可回看的版本**；用户可以在面板顶部切换。

## 1. 什么时候产生一个版本

只认「一次任务完成」，不认每一次写入。

| 触发 | 是否成版本 |
|---|---|
| agent 在一次回复里改完并收尾（改字、改长度、改配色、重画一幕） | 是 |
| 用户在面板里改字/拖段长/改配色 | 否（先攒着，归入下一个版本） |
| 导出、播放、切换预览 | 否 |

实现上版本由 **agent 主动落**（CLI），因为只有它知道「这一轮改完了、改的是什么」。

```sh
dsh-motion version -m "把 1945 的图钉改成红色"     # 落一个版本，标题就是这句
dsh-motion versions                                 # 列表
dsh-motion use v3                                   # 切换（追加式，见 §3）
```

skill 里加一条硬规则：**每次改完，收尾前必须落一个版本**，标题写「用户看得见的变化」，不是「updated files」。
面板也兜底：如果工作区有未归版的改动，顶部下拉显示「未保存的修改」。

## 2. 文件结构

```
motion/
  timeline.json
  scenes/*.mjs
  assets/                  # 大文件只在版本清单里引用，不复制
  .versions/
    v1.json
    v2.json
    …
  .snapshots/              # 现有的逐次写入快照（内部撤销用，不面向用户）
```

一个版本清单（全量，不做 diff——timeline 与场景源码都只有 KB 级）：

```json
{
  "id": "v3",
  "at": "2026-10-24T05:12:41Z",
  "title": "把 1945 的图钉改成红色",
  "author": "agent",
  "timeline": { …完整 timeline… },
  "scenes": { "orbits.mjs": "…源码…" },
  "assets": { "plate": "assets/plate.png" }
}
```

- timeline + 场景源码**全量存**：实现简单、恢复可靠，几 KB 的事。
- assets 只存路径：图片/视频不进版本，避免仓库膨胀。

## 3. 切换的语义：只追加，不跳转

选 v2 不是「回到过去」，而是：

1. 先把当前状态落成一个新版本（`v7 "切到 v2 之前"`）；
2. 再把 v2 的 timeline + 场景写回工作区；
3. 立刻落一个 `v8 "回到 v2"`。

结果：历史永远不丢，任何一步都能再切回来。用户看到的下拉是线性的一串，而不是可能分叉的树。

切换需要**重载预览**（场景源码变了，浏览器缓存模块），面板会提示一次。

## 4. 面板 UI

顶部条左侧（现在空着的位置）放一个下拉：

```
[ 版本 ▾ ]   v3 · 把 1945 的图钉改成红色
             ─────────────────────────
             v5  改了片尾语速            (agent · 2 分钟前)
             v4  换成浅色配色            (我 · 5 分钟前)
             v3  把 1945 的图钉改成红色   (agent · 12 分钟前)  ← 当前
```

- 每行：编号、标题、作者、时间；当前版本打点；
- 切换前弹一句「会先保存当前状态」的确认（避免误点）；
- 导出按钮和版本无关，始终导出当前工作区。

## 5. 与现有 snapshot 的关系

`dsh-motion` 现在每次写入都会存一份 `timeline.json` 快照（`.snapshots/`），那是**内部撤销日志**，几十毫秒粒度。

版本是**面向用户的历史**，粒度是一轮任务。两者不合并：

- snapshot 继续存在，用于「回退」（如果保留回退按钮）；
- version 存 timeline + 场景源码，用于跨「改了代码」的恢复——快照做不到这点（它只存 timeline）。

这也是为什么回退按钮可以去掉了：版本切换覆盖了它，而且能连场景代码一起恢复。

## 6. 需要你拍板

1. **触发**：只由 agent 主动 `dsh-motion version` 落地，还是也在「面板改动后空闲 30 秒」自动落一个（author=user）？
2. **全量 vs 增量**：我倾向全量（timeline + 所有场景源码），简单且几 KB；增量需要在恢复时重放 diff，出错面大。
3. **切换是否追加**：我倾向追加（永不丢历史），代价是切来切去会让列表变长。你是否接受？
4. **版本要不要带缩略图**：带的话每次落版本要渲染一张 320×180 的静帧（约 0.3 秒），下拉里更直观；不带就纯文字。
