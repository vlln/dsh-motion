# howto · 怎么办一件事

这个目录里是**做法的规程**，不是契约，也不是资料。每一份回答一个「遇到这种活，怎么做」。

引擎（`src/`）只管载具；`kit/` 是可删的代码样例；`cards/` 是一个风格的全部知识；
`showcase/` 是**给用户看的样板库**（空工作区的画廊），引擎不引用，agent 也没有它的工具。
这里是夹在中间的那层：**手艺的做法**。

| 文件 | 什么时候读 |
|---|---|
| [`新风格.md`](新风格.md) | 要做一种没做过的风格 |
| [`从参考里取.md`](从参考里取.md) | 画出来不像、或者分数上不去 |
| [`角色.md`](角色.md) | 画面里要有人 |
| [`镜头表.md`](镜头表.md) | 开工前定画风和每一镜的物 |

| [`交付.md`](交付.md) | 要交片 |

## 三条规矩

1. **这些是做法，不是配额。** 有更好的做法就写回来，把旧的那句改掉。
2. **不写「应该」的话。** 每一句要么能执行，要么能验证；不能的删掉。
3. **证据要跟结论一起写。** 「量色板比手挑准」后面跟着 47→65 和三个色值对比，
   不是一句「经验之谈」。

## 名字的由来

以前这个目录叫 `protocol`，是从参考仓库的「16-风格演示95分协议」借的词。
借错了：英文 protocol 指的是通信协议，不是做法规程；而且没人知道它是什么。
`howto` 说的是它真的装的东西——怎么办。
