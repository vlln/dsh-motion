# 交付

三道，按顺序。**前一道没过，不许开下一道。**

## 1. 事实：`check --deliver`

```sh
dsh-motion render --video        # 出片
dsh-motion check --deliver       # 量这部片
```

它只断言能证明的事：

| 红灯 | 含义 |
|---|---|
| 没有画面 | 文件里没有视频流 |
| 没有声音 | 没有音轨 —— 先写 `motion/audio.json`，再 `make-audio.mjs --write` |
| 长度不对 | 片长和时间线差 0.5 秒以上 |
| 空画面 | 连续 0.3 秒以上几乎纯色（量法：降到 96×54，逐帧算亮度标准差，< 4 记为近纯色） |
| 幻灯片 | 一半以上的相邻帧完全一样 |
| 蓝紫雾 | 蓝紫像素占全片 30% 以上（题材确实需要时 `--allow-blue-purple "理由"`，理由写进交付说明） |

它**不断言**：构图好不好、像不像那个风格、值不值得看。那些是第 2、3 道。

**静止不是病。** 壁画、解说片本来就有大段停住；只有「整片不动」才是病。

## 2. 眼睛：并排对照 + 打分

- 抽帧排成一排，对着镜头表看：哪一镜像从别的片子里拿来的，重做。
- 有参考的，把成片和参考摆在一起（`out/look/vs-ref.jpg`），回答一个问题：**去掉名字还认得出吗？**
- 按 [`审片.md`](审片.md) 的四个问句答；两条硬闸门（媒介硬指标缺两条、主体图标化）任一成立就不算做完。

## 3. 外人：独立审片

**派一个没参与制作的 agent，只看成片，挑问题。**

- 它不看代码、不看你的自评、不看镜头表。
- 结论写进 `motion/审片/*.md`：看到了什么、哪里看不懂、哪里像模板、哪里不该动。

### 派不出人的时候

**四次冷启动，四次都派不出**（子会话的委派深度到顶）。所以这一条要写清退路：

1. 跑一次能派的——如果你还有委派深度，就派；
2. 派不出，就写 `motion/审片/01-自评.md`，**第一行标明「自评，不是独立审片」**；
3. 在交付说明里明写这一道**没做**，不要用自评顶替；
4. 自评里列出「如果有人在看，我希望他看哪三处」——那是给下一个人省的时间。

**自评不能当独立审片用。** 这九轮里自评比盲评平均高 20–35 分，
用自评顶替等于把这一道门直接拆了。

## 声音

写 `motion/audio.json`（一份谱子：哪一拍、什么音色、多响），然后：

```sh
node skills/dsh-motion/scripts/make-audio.mjs --write
```

它会渲染 `motion/assets/audio/bed.wav` 和 `out/audio/wave.png`，并把 `timeline.audio` 指过去；`render` 时自动混进去。
`audio.json` 里的 `length` 可以不写——不写就跟着片长；写了必须和片长一致，否则报错。
已经有自己的音轨就直接写 `timeline.audio.src`。

## 最后

- 做对了的事写进卡的「管线」；新坑写进卡的「坑」；被推翻的结论**改掉原句**，不要留着。
- 状态栏按三档登记：研究配方 / 单场景实做 / 跨场景验证。**没走过六步不许写实做。**
