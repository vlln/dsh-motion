# 从参考里取

做一张卡的时候，有三样东西**不需要发明，直接取**：色板、表面、人物。
参考就在手里——一张帧、一段源码、一次生成。取比造快，也比造准。

下面每条都附九轮盲评的记分，作为证据，不是作为目标。
**别把分数当目标**：这次会话里我就犯过——评审说「线宽应该 6–7px」，我把默认值改成 5.6，
那是照着数字调参。分数是事后记的，做法才是事前要定的事。

## 证据（埃及那张卡，九轮）

| 改动 | 分数 | |
|---|---|---|
| 照参考量色板，换成矿物色 | 47 → 65（+18） | 取 |
| 人物改成生图 + 代码合成 | 52 → 61（+9），两次一票否决消失 | 取 |
| 照参考源码重做表面（fBm 墙 + multiply + 裂纹） | 61 → 64，媒介 7→9 | 取 |
| 把人物改成「埃及程式」（我猜的意图） | 65 → 52（−13） | 造 |
| 加接触影 + 带翼日轮（参考里没有） | 61 → 60（−1） | 造 |

规律：**取的三次都涨，造的两次都跌。**

## 一、色板：量，不要挑

手挑的色板**系统性偏亮、偏灰**。实测：

| | 参考帧（量的） | 手挑的 |
|---|---|---|
| 蓝 | `#274f87` | `#3a5a8c` |
| 墙 | `#d2bf93` / `#d9c79b` | `#e4d5b4` |
| 红 | `#72281b` | `#9c4030` |

```sh
node scripts/palette-from.mjs 参考帧.png --colors 8 --out out/ref-palette.png
```

它打印每种颜色**占画面多少**。占比最大的通常是墙/地——那是观众读成「这幅画」的颜色。
**输出直接写进场景的色表。**

量具也能指出肉眼看不见的缺口。同一张卡：

```
参考：蓝 26.2% · 墙 23.9% · 墙 22.6% · 橄榄 13.6% · 砖红 10.1%
我们：蓝 35.8% · 墙 24.9% · 墙 12.9% · 褐  9.8% · 墙  9.1%
```

水带多了九个点；参考里 10% 的砖红我们一个都没有。这两条以前要等盲评说，
现在一条命令就能看见。

## 二、表面：参考是代码，就读参考的代码

我在表面这件事上造了五轮（逐像素抖动 → 低频斑 → 块状剥落），全部被打回。
最后读参考的 `02_egypt.js`，它是：

```js
// 墙：一张现画的 fBm 纹理，不是平涂
P.texture(key, base, { scale: 0.004, amt: 26, grain: 14 })    // 5 个八度
// 表面：整幅 multiply 一层，2×2 像素一块写
v = 243 + fbm(x*0.006, y*0.006, 4)*30 + fbm(x*0.03, y*0.03, 2)*12 + (r()-0.5)*18
// 六条随机游走的发丝裂纹也画进这一层——所以裂纹跨过人物，那是墙老了
```

照抄之后：媒介 7 → 9，单帧 10.1ms → **0.18ms**（重活挪到 mount 一次）。

**只要参考是可读的代码，先读完再动手。** 省下的不是时间，是五轮返工。

## 三、人物：生图给，代码合成

九轮里代号画人被一票否决五次。换成生图之后第一次两项否决都没触发，
盲评原话「小孩是全场最好的」「作为卡通它是成立的」。

关键不在生图本身，在后一步：**压色板**。让生图的颜色并进画面的色板，它才不像贴纸。
细则在 [`角色.md`](角色.md)。

## 四、尺子要钉死，一张

同一张画面，按博物馆壁画判 → 造型 5/15、否决；按原片那一帧判 → 造型 8/15、不否决。
**差 13 分，全是尺子的差别。** 卡的第一行写「我对照的是哪一张」。

## 五、参考里没有的，不要加

接触影（签名 −5）、带翼日轮（整体 −1）。评审是拿**这一张参考**在比，
不是拿「这类艺术的通识」在比。

## 先做哪件

| 先做 | 为什么 |
|---|---|
| 量色板 | 颜色对了，画面立刻「是那个东西」 |
| 抄表面 | 媒介是最容易被判「矢量图」的一项，也最容易靠抄解决 |
| 生图给人物 | 否决项不清，后面做得再好也不算数 |

墙的密度、层序、接地是收尾——它们决定 80 还是 85，不决定 60 还是 80。

## 一句话

> **能取的就取，取不到的才自己造。**
> 先量色板，再读源码，再找人要人物——三件事做完再谈设计。
