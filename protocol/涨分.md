# 什么让分数变高

这一页不是审美主张，是**归因记录**。埃及那张卡跑了九轮盲评，每次改动和分数变化都记在案，
规律非常干净：

| 改动 | 分数 | 类型 |
|---|---|---|
| 照参考量色板，换成矿物色 | **47 → 65（+18）** | 搬 |
| 人物改成生图 + 代码合成 | **52 → 61（+9）**，两次一票否决消失 | 搬 |
| 照参考源码重做表面（fBm 墙 + multiply + 裂纹） | 61 → 64，媒介 7→9 | 搬 |
| 把人物改成"埃及程式"（我猜的意图） | 65 → 52（**−13**） | 发明 |
| 加接触影 + 带翼日轮（参考里没有） | 61 → 60（**−1**） | 发明 |

**三次涨分全是"把参考里已经存在的东西搬过来"；两次掉分全是"我以为它该有"。**

---

## 五条规则（按涨分从大到小）

### 1. 色板要量，不要挑

手挑的色板**系统性偏亮、偏灰**。实测：

| | 参考帧（量出来的） | 手挑的 |
|---|---|---|
| 蓝 | `#274f87` | `#3a5a8c` |
| 墙 | `#d2bf93` / `#d9c79b` | `#e4d5b4` |
| 红 | `#72281b` | `#9c4030` |

```sh
node scripts/palette-from.mjs 参考帧.png --colors 8 --out out/ref-palette.png
```

它打印每种颜色**在画面里占多少**——占比最大的那个通常是墙/地，也就是观众读成"这幅画"的颜色。
**把输出直接写进场景的 C 表，不要凭印象改。**

### 2. 媒介去参考的源码里抄，不要自己发明

我在表面这件事上发明了五轮（逐像素抖动 → 低频斑 → 块状剥落），全部被打回。
最后**读参考的 `02_egypt.js`**，发现它是：

```js
// 墙：一张现画的 fBm 纹理，不是平涂
P.texture(key, base, { scale: 0.004, amt: 26, grain: 14 })   // 5 个八度
// 表面：整幅 multiply 一层，2×2 像素一块写
v = 243 + fbm(x*0.006, y*0.006, 4)*30 + fbm(x*0.03, y*0.03, 2)*12 + (r()-0.5)*18
// 再画六条随机游走的发丝裂纹进去（所以裂纹会跨过人物）
```

照抄之后：媒介 7 → 9，单帧从 10.1ms 降到 **0.18ms**（重活挪到 mount 一次）。

**只要参考是可读的代码，先读完再动手。** 这一步省掉的不是时间，是五轮返工。

### 3. 人由生图给，代码只合成

九轮里代号画人有五次被一票否决。换成生图之后：

- 第一次两项否决都没触发，盲评原话「小孩是全场最好的」「作为卡通它是成立的」；
- 关键不是生图本身，是**后面那一步压色板**——让生图的颜色并进画面的色板，它才不像贴纸。

细则在 [`角色.md`](角色.md)。

### 4. 对照物必须钉死，一张

同一张画面，按博物馆壁画判 → 造型 5/15、否决；按原片那一帧判 → 造型 8/15、不否决。
**尺子错了，分差 13。** 卡的第一行就要写「我对照的是哪一张」。

### 5. 不要加参考里没有的东西

接触影（−5 签名）、带翼日轮（−1 整体）。每个"我觉得该有"都在扣分，
因为评审是拿**这一张参考**在比，不是拿"埃及艺术的通识"在比。

## 顺序

分数不是均匀分布的。按这九轮的实测，先做这三件能把 60 分推到 80：

| 先做 | 能拿 | 为什么 |
|---|---|---|
| 色板量准 | 签名 + 构图 ≈ +10 | 颜色对了，画面立刻"是那个东西" |
| 媒介照源码搬 | 媒介 20 分项里 +8~10 | 最大单笔失分，且最容易被判"矢量图" |
| 人物生图 | 造型 +3，且解掉一票否决 | 否决项不清，分数再高也不算数 |

**剩下的（墙的密度、层序、接地）是收尾，不是杠杆。** 它们决定 80 还是 85，不决定 60 还是 80。

## 一句话

> **能搬的都搬，不能搬的才自己造。**
> 先量色板，再读源码，再找人要人物——三件事做完再谈设计。
